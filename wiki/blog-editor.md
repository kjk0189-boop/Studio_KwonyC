# Blog 원고와 관리자 글쓰기

## 확인한 방향

- Studio KWONYC에 원문을 발행하고 Velog·네이버 블로그·티스토리는 보조 채널로 사용한다.
- 상단 메뉴 이름은 Blog로 하고, 홈에서도 최신 글을 열 수 있게 한다. 목록에서는 전체, AI 캠프 회고, 일상으로 글을 찾고 필요할 때 카테고리를 추가한다.
- 로컬 미리보기에서 메뉴별 화면, 카테고리 필터, 관리자 글쓰기의 제목·분류·본문 입력과 간단한 미리보기·브라우저 임시저장을 만들었다. 실제 사이트의 로그인·발행 연결은 구현 전이다.

## 제안하는 원고 규격

**Markdown을 공통 원본으로 하고, 직접 작성·붙여넣기와 .md 파일 불러오기를 같은 편집기로 연결한다.** 파일은 불러온 뒤 제목·카테고리·본문을 확인하고 수정할 수 있게 한다. 관리 화면에서 입력한 메타데이터와 원고가 일치하도록 저장한다.

- 공통 항목은 제목, 카테고리, 한 줄 소개, 본문이다. 발행일은 발행 시 확정하고 주소는 글마다 유지한다.
- 본문은 제목, 문단, 목록, 링크, 인용, 코드 블록, 이미지와 대체 텍스트를 공통으로 지원한다.
- 회고는 기간·학습 범위, 배운 점, 실제 실습이나 문제 해결, 다음에 해볼 일을 기본으로 둔다. 일상 글은 필요한 소제목만 쓴다.
- 네이버 블로그 원고는 붙여넣기나 재편집에 사용할 수 있다. 네이버 화면의 글꼴·여백·이미지 배치까지 그대로 재현하는 방식은 확인이 필요하다. 1차는 공통 구조를 유지하고 각 채널 미리보기에서 서식을 확인한 뒤 사용자가 직접 발행한다.

## 이미지 처리 제안

관리자에서 이미지를 첨부하면 사이트가 관리하는 자산에 저장하고, 본문에 경로와 대체 텍스트를 삽입한다. .md 파일에 로컬 상대 경로가 있으면 함께 올릴 이미지가 있는지 확인하고 누락을 알려준다. 네이버 원고의 이미지는 원본 파일을 다시 첨부하는 흐름부터 지원한다. 공개 페이지의 용량은 이미지 크기 조정과 화면 아래 이미지 지연 로딩으로 관리한다.

## 구현 순서와 미결 사항

1. 공통 Markdown 규격과 글 예시로 제목·본문·코드·이미지 렌더링 확인.
2. 관리자에서 직접 입력과 .md 불러오기, 미리보기, 초안 저장을 연결.
3. 관리자 로그인, 이미지 자산 저장, 정적 공개 글로 내보내는 발행 방법을 결정하고 검증.

공개 Blog에는 관리자 편집기를 불러오지 않는다. 로그인 방식, 이미지 저장 위치와 용량 기준, 발행 및 되돌리기 방식은 구현 전에 확정한다. 관련 결정과 검증 결과는 이 문서, [위키 목록](README.md), [작업 일지](work-log.md)에 이어서 기록한다.
